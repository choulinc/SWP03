04 / FOUNDATION

核心模型與控制

先理解 5-DOF MJCF 的關節約定，再理解輸入控制目標後為什麼還需要物理時間推進。

ROBOT MODEL

五軸運動學

J0Base yaw−160°～180°
J1Shoulder pitch−90°～180°
J2Elbow pitch−142°～142°
J3Wrist pitch−135°～135°
J4Tool roll連續轉動

J0 使用保守限位政策；實際機型版本仍需核對。TCP 預設和 flange 共點、沒有夾爪延伸。

CONTROL LAW

位置致動器不是瞬間移動

τ ≈ clip[kp(qtarget − q) − kvq̇]

set_target() 設定角度目標；position actuator 根據近似伺服模型產生力矩，mj_step() 才會更新系統動態。

物理 dt0.002 s
2000 steps4 s 模擬時間
內部單位m · rad · s · kg
Python · headless minimal
import numpy as np
from dorna2_mujoco.simulation import Simulation

sim = Simulation()
sim.controller.set_target(np.deg2rad([20, 35, -60, 25, 45]))
sim.step(2000)
print(sim.joint_positions)  # radians
print(sim.tcp_position)     # metres, world/base frame

05 / EXTENSIONS

CAD 與離線 SDK

兩個擴充解決完全不同的問題：CAD 提供視覺外觀，SDK 提供官方指令介面的一致性。

CAD PIPELINE

STEP → 場景外觀

01STEP + 註冊 profile來源 hash、六個組件、座標轉換
02Mesh / scene.xml只新增 visual mesh，維持 physics primitives
03本地場景部署scene + meshes 複製到 runtime，轉換工具不必跟著移動
廠商 STEP 與產生的 mesh 不放入 Git 或公開 site；CI 以原創 CC0 test boxes 驗證。外觀更像實機 ≠ 動力學更準確。
OFFLINE SDK BRIDGE

官方 helper → MuJoCo

01Vendor SDK 2.1.2jmove / sleep / joints readback
02Commands queue五軸目標、速度／加速度／jerk、狀態
03Simulated motionSDK 邊界 degrees；物理核心 radians
僅模擬 adapter；不會連接真實手臂。Cartesian、continuous blending、I/O 與硬體操作尚未支援。
檔案角色
src/dorna2_mujoco/cad.py ↗STEP → 網格轉換與 registration
src/dorna2_mujoco/usd.py ↗USD articulation 與物理參數轉換
src/dorna2_mujoco/commands.py ↗軌跡佇列、狀態與 input validation
src/dorna2_mujoco/official.py ↗原廠 SDK helper 的離線 adapter

SDK 控制範例

有限能力

0 → 1 → 2 = accepted → started → planned complete。completed 不是「實機軌跡零誤差」。

Python · actual vendor SDK / simulation
from newton_dorna import connect_sim

with connect_sim() as robot:
    robot.resume()
    robot.jmove(j0=10, j1=35, j2=-60, j3=25, j4=30,
                rel=0, vel=30, accel=60, jerk=240,
                cont=0, timeout=0)
    robot.sleep(0.5)
    print(robot.get_all_joint())

08 / DEPLOYMENT · NEW

H100 與 CUDA 12

將不同層級的驗證分開：硬體可算 CUDA、Newton 實際物理可跑、完整 PPO stack 可重現，是三個獨立問題。

✓

Host CUDA Compute

H100-20C 的既有 Torch 2.9.1+cu128、Warp 1.18.0+cu12 執行算術、矩陣乘法、Warp kernel 與 interoperability 測試。

已有主機測試紀錄
✓

Newton 遠端模擬

H100 實際 100-step smoke、Mac viewer 150+ frames、SDK 動作／查詢通過；非實時物理速度。

特定 VM / native runtime 已測
!

CUDA 12 PPO Stack

獨立 cu126 profile 與分階段 acceptance 已有程式碼，但尚無完整 H100 lock resolution / GPU 訓練／qualification 成功結果。

待驗證
CURRENT / ORIGINAL

原 RTX CUDA 13 實驗

Torch2.12.0+cu130Warp1.17.0Newton1.6.1MuJoCo/MJWarp3.12.0

原始 GPU lock 保留，已在 RTX 工作站驗證；不是 H100 最新 driver 直接可用的保證。

CANDIDATE / SEPARATE

cu126 候選路徑

Torch2.12.0+cu126Warp1.17.0Newton1.6.1Statusunresolved / unqualified

依獨立 profile 安裝，不修改原 lock；候選方案不等於已完成 H100 訓練。

Bash · cu126 preflight (不建立 GPU 環境)
python3 experiments/isaaclab_newton/scripts/accept_cu12.py \
  --check --output /tmp/dorna2-cu126-preflight \
  --bootstrap-python /path/to/existing/python-with-pip

完整 acceptance 的階段依序是依賴解析、版本／import、CUDA 診斷、Cartpole smoke、UR10 smoke、checkpoint reload／評估、Dorna primitive MJCF qualification。本頁不宣稱這些完整階段已在 H100 通過。
